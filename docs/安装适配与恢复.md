# 使用前需要改什么

本 EFI 是参考机维护记录。先保存自己能启动的 EFI 和救援 U 盘，再准备公开副本；没有本机身份、Windows 引导或个人恢复资料。

## 必须自行核对

1. **SMBIOS 四项**：使用 [GenSMBIOS](https://github.com/corpnewt/GenSMBIOS) 等工具为适合自己的机型生成 SystemSerialNumber、MLB、SystemUUID，填写自己的 6 字节 ROM。当前为留空/全零占位，不能照搬别人身份。MacPro7,1 只是本机现用设置，不等于所有机器最合适的机型。
2. **AMD 物理核心数**：`Kernel/Patch` 前四项注释包含 `cpuid_cores_per_package`；当前常量为十六进制 `04`，对应 4 个物理核心，不是线程数。改其他 CPU 时需按 [AMD Vanilla](https://github.com/AMD-OSX/AMD_Vanilla) 当前方法处理四个版本范围，不能只改一项或替换全部 `04` 字节。
3. **主板/BIOS/ACPI/MMIO**：本机四个 SSDT 的命名空间和 MMIO 白名单不可仅凭同一 CPU 推断兼容。重新核对 PCI/ACPI 路径、USB 控制器、BIOS 内存映射。
4. **目标系统**：当前版本组合为 Tahoe / Darwin 25；AirportItlwm、传感器插件及 AMD 补丁都有版本范围。其他系统必须选择对应驱动/补丁，不能只改 MinKernel 强行加载。
5. **硬件驱动**：有线、Wi-Fi、蓝牙、音频、触控板、电池分别看真实硬件。公开版禁用了未随包分发的旧 CtlnaAHCIPort；如果你的系统盘或其他关键磁盘依赖特殊 SATA 控制器，要先解决对应驱动再测试。
6. **USB**：当前是通用 UTBDefault，不是完整定制映射；按自己的物理接口测试。没有 AppleALC 等不等于可以给任意 codec 加同一个 layout-id。

BIOS 中实际 CSM、Secure Boot、IOMMU、SATA、UMA 显存等设置未完成逐页取证，因此不声称本机已经按某一套通用清单设置。UEFI 固件 Secure Boot 与 config 的 SecureBootModel 是不同层面的设置。不要照抄 Intel VT-d/CFG Lock 项到 AMD 机器。

## 检查与 U 盘试启动

在 macOS x86_64、Python 3.9+ 下，可运行：

```sh
python3 tools/check_efi.py
python3 tools/check_efi.py --require-identity
```

第一条检查文件引用和发布清单；第二条还会检查个人身份项已填写。修改个人配置后清单哈希不匹配是预期的，此时使用 `--skip-hashes --require-identity` 检查自己的副本。检查工具只读文件，不挂载、不改写 EFI。

另从 [匹配的 OpenCore 1.0.9 包](https://github.com/dortania/build-repo/releases/tag/OpenCorePkg-78d5ff8) 获取 `ocvalidate`：

```sh
/path/to/ocvalidate EFI/OC/config.plist
```

结构校验通过不等于能启动。将整个 `EFI` 目录复制到测试 U 盘 EFI 分区，在 BIOS 一次性启动菜单选择 U 盘 UEFI 入口。保留可启动的原 EFI；首次不要覆盖内置启动分区。

OpenCanopy 当前 `Timeout=0`、`ShowPicker=true`，会等待手动选择；空格显示辅助项。确认可用后如需自动倒计时，将 Timeout 改成所需秒数。Ctrl+Enter 可在允许时保存默认系统；BIOS 的默认入口仍要另行确认。

## 内置安装、停止与恢复

只有 U 盘试启动成功、关键设备核验后才迁移到内置 EFI。EFI 分区位置由实际磁盘布局决定，不要求跟参考机使用相同 disk 编号。

安装前完整备份原分区启动文件到独立磁盘。若已有 Windows，保留 `EFI/Microsoft`，先备份原 `EFI/BOOT/BOOTx64.efi`；替换 fallback 入口会改变启动路径。这个包不包含个人 Windows BCD，不会替你建立默认 BIOS 项。

停止使用时，从 BIOS 选择原启动管理器，或从救援 U 盘启动后恢复自己的 `OC` 与原 fallback 文件；不要用其他人的备份覆盖 Windows 或 APFS 数据。OpenCore/驱动变更通常在重启后生效，不在运行中热卸载 VirtualSMC 或显卡插件。

## EFI 只读挂载失败的本机记录

本机 `diskutil mount readOnly` 曾失败，日志记录 FSKit 检查 FAT 返回 200，尚未证明分区损坏。系统自带传统 `mount_msdos -o rdonly` 挂载成功，随后确认只读标志和实际文件。这个记录不是让所有人修复或格式化 EFI。

如需采用传统工具，先确认目标分区和已存在的空目录，使用本机实际编号：

```sh
sudo /sbin/mount_msdos -o rdonly /dev/diskNsM /path/to/empty-mountpoint
```

其中 `diskNsM` 和路径均为占位。不要复制参考机编号去挂载未知分区，更不要用格式化命令替代读取。
